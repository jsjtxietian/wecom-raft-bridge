# 企业微信 ↔ Raft 文本桥接

把企微私聊或群聊发给智能机器人的文本交给 Raft agent，再把 agent 回复送回发起任务的会话。桥接用独立 External Agent 身份运行，不调用模型、不执行任务、不调度 agents。

## 让 AI 帮你安装

**把下面这段话复制给能访问本地文件、运行终端命令的 AI 编程助手**，让它完成安装、配置和验证。准备好企微机器人的 API 长连接凭据，以及 Raft External Agent 凭据即可；缺少的信息，助手会集中询问。已有 Raft 执行 agent 会继续负责处理任务。

```text
请帮我把企业微信 ↔ Raft 消息桥接部署到本机，并完成启动验证：
https://github.com/jsjtxietian/wecom-raft-bridge

请直接执行你能完成的步骤，不要只给我安装教程：

1. 检查操作系统、Git、Node.js 22+ 和 npm。已有本地仓库时优先复用，否则克隆到合适目录；沿用我现有的 Git 认证和网络配置。先阅读仓库中的 README.md、.env.example、package.json 和 docs/architecture.md，以实际版本为准，不覆盖已有工作。
2. 安装项目依赖。保留已有 .env 的有效配置，只补缺项；没有 .env 时从 .env.example 创建。优先通过已有配置和只读查询确定 Raft 身份、频道及成员，不把示例名称当作我的配置。
3. 集中向我询问仍缺少的信息：企微 Bot ID、Secret、机器人显示名；Raft 服务地址、桥接 External Agent 凭据及其 @handle、目标频道、现有执行 agent 的 @handle。凭据通过本地文件或安全输入填写，不在回复、日志或 Git 中暴露。告诉我在 .env 的哪个变量填写；缺少凭据时先完成安装和离线验证，不编造配置或成功结果。
4. 默认开启私聊和群聊，使用范围由企业微信侧控制，无需填写群 ID。复用现有 Raft 执行 agent，确认桥接身份及执行 agent 已加入目标频道；如缺少机器人或 External Agent，请指导我创建并提供对应凭据。桥接本身不需要模型 API Key，也不需要公网回调地址。
5. 按仓库文档执行类型检查、离线测试和真实 Raft 身份检查。启动前查看运行状态，已有实例时复用；需要加载新配置时正常停止再启动，避免同一机器人开多个长连接。使用项目的跨平台后台启动入口，核对状态及企微认证日志，不设置开机自启。
6. 启动成功后，让我私聊机器人，或在群里从 @ 菜单选中机器人发送一条测试任务；核对消息进入 Raft 对应 thread，并收到企微回传成功回执。需要时提醒我让执行 agent 在该 thread 内回复。尚未完成真实往返时如实标明。
7. 最后简短告诉我：项目路径、当前状态、启动/停止/查看状态的方法、日志位置，以及还缺哪些信息。介绍私聊连续追问、引用提问和单独发送 /new 切换话题的用法。
```

这是给部署助手的提示词，不是发送给企微机器人的命令。也可以按下方步骤手动安装。

示例路由：`StoryLoom客服 → #StoryLoom_Wecom → @Sol`，桥接身份为 `@WeCom`；请替换为自己的机器人、频道及 agent。私聊、群聊默认均开启；允许哪些人或群使用，由企业微信侧的白名单控制。

## 启动

Windows、macOS、Linux 均需要 Node.js 22+（含 npm），并能访问企微与 Raft。先在项目目录安装依赖：

```sh
npm ci
```

首次安装时复制配置模板；已有 `.env` 时不要覆盖。Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

macOS / Linux：

```sh
cp .env.example .env
```

编辑 `.env` 填完下方配置，再检查身份并启动（三个平台命令相同）：

```sh
npm run check
npm run start:bg
```

`npm run check` 只验证 Raft 身份、频道和目标 agent，不发消息；启动显示“企微已认证”后可收消息。如果显示“启动中”或“等待企微连接”，用 `npm run status` 查看后续状态，错误详情在 `.local/bridge.stdout.log` 和 `.local/bridge.stderr.log`。

### 日常一键启动

安装及配置完成后，Windows 可直接双击根目录的 `bridge.cmd` 后台启动，提示后关闭窗口即可。三个平台也可从终端调用：

| 操作 | 所有平台（项目目录内） | Windows PowerShell | macOS / Linux |
| --- | --- | --- | --- |
| 后台启动 | `npm run start:bg` | `.\bridge.cmd start` | `sh ./bridge.sh start` |
| 查看状态 | `npm run status` | `.\bridge.cmd status` | `sh ./bridge.sh status` |
| 停止 | `npm run stop` | `.\bridge.cmd stop` | `sh ./bridge.sh stop` |
| 前台运行，看实时日志 | `npm start` | `.\bridge.cmd run` | `sh ./bridge.sh run` |

脚本也可用绝对路径从其他目录调用，路径含空格时加引号；配置和日志始终从项目目录读取。`bridge.sh` 默认操作是后台启动，使用 `sh` 执行无需设置可执行权限。macOS 用户请从终端运行，双击 `.sh` 的默认行为取决于系统设置。

重复启动会显示已有进程状态，不再创建第二条连接。`npm run stop` 通过本机控制接口通知桥接完成正在投递的消息后停止，通常几秒完成，最长等待约 30 秒；前台运行也可按 `Ctrl+C`。后台进程退出后不会自动重启，不注册开机自启，不修改系统休眠设置。修改 `.env` 或更新代码后，先 stop，再 start:bg。

防重复启动以同一台机器上的项目目录为范围，`discover` 也占用同一实例；不同目录副本或不同机器仍需自行保证同一个机器人只开一个连接。**从旧版升级时，先停止旧版桥接再使用新脚本**，旧进程没有控制接口，`status` 无法识别它。

## 配置

程序只读取 `.env` 和环境变量（环境变量优先），不再读取 `bot.txt` 或 `token.txt`。

| 变量 | 用途 |
| --- | --- |
| `WECOM_BOT_ID` | 智能机器人 Bot ID |
| `WECOM_SECRET` | 智能机器人 Secret |
| `WECOM_ALLOW_PRIVATE` | 是否接收私聊，`true` / `false`，默认 `true` |
| `WECOM_ALLOW_GROUP` | 是否接收群聊，`true` / `false`，默认 `true` |
| `WECOM_BOT_NAME` | 群内机器人显示名，用于去掉开头的 mention |
| `RAFT_SERVER_URL` | Raft 服务地址 |
| `RAFT_AGENT_CREDENTIAL` | 桥接身份的 `sk_agent_...` 凭据 |
| `RAFT_CHANNEL` | 固定频道，例如 `#StoryLoom_Wecom` |
| `RAFT_TARGET_AGENT` | 默认执行 agent，例如 `@Sol` |
| `RAFT_EXPECTED_AGENT` | 桥接身份，例如 `@WeCom`，启动时校验 |
| `RAFT_POLL_MS` | Raft 轮询间隔，默认 2000 毫秒 |

`.env`、旧凭据 txt、运行日志、`node_modules/`、`.local/` 和参考源码 `ref/` 均被 Git 忽略。仓库只提交不含密钥的 `.env.example`。无需模型 API Key、公网回调地址或内网穿透。

## 私聊和群聊

私聊直接发文本；群聊从企微的 @ 菜单选中机器人后发文本。新群只需在企微侧允许使用并加入同一机器人，无需发现或填写群 ID。原来的 `WECOM_CHAT_ID` 已不再读取。

例如只接收群聊，在 `.env` 设置后重启：

```dotenv
WECOM_ALLOW_PRIVATE=false
WECOM_ALLOW_GROUP=true
```

设为 `false` 的消息类型会静默忽略，两个开关都可关闭。仅接受当前 Bot ID 的回调，不另设用户或群白名单。

`npm run discover` 保留为排错工具：先停止主服务，再运行它，观察私聊/群聊回调是否抵达。它只记录会话类型、会话 ID、发送者 ID 和消息 ID，不执行或回传任务。

## 消息效果

在企微发送 `@StoryLoom客服 请检查这个问题`，Raft 中会收到：

```text
@Sol

请检查这个问题
```

不再附加来源标签、发送者 ID 或消息 ID。`@Sol` 用于触发执行 agent；正文中的邮箱、代码和其他 mention 保留。

在企微中引用一条文字消息，再输入问题即可携带引用上下文。群聊仍需要 @机器人；私聊直接提问。例如引用“暂不支持导出人物表”，再问“那可以导出哪些内容？”，Raft 会收到：

```text
@Sol

引用内容：
> 暂不支持导出人物表

本次提问：
那可以导出哪些内容？
```

支持引用文本和图文混排中的文字；非文字部分会注明未读取，不下载附件。仅引用而未输入问题时，会提示输入任务内容。引用中的 Raft `@handle` 显示为全角 `＠handle`，避免历史 mention 再次唤醒 agent；邮箱和本次问题里的 mention 保留。

引用作为本次问题的上下文，不根据引用文字猜测旧任务，也不会拉取聊天历史。私聊仍发往该用户的固定线程；群聊仍独立发起任务。历史读取 MCP 暂未接入。

**私聊连续使用同一个 Raft thread**：某个用户首次私聊会在 Raft 频道发起消息并建立线程；后续私聊直接发入该线程，每次仍 `@Sol`。例如先问“能导出人物表吗？”，再发“那有哪些字段？”，Sol 可以在同一线程读取上下文。不同用户各自一个当前线程，不自动超时切换。

**换话题时，私聊单独发送 `/new` 或 `新话题`**。收到“已切换新话题，请发送新的任务。”后，再发任务，便会创建新的 Raft thread。命令由桥接处理，不唤醒 agent；只影响当前私聊用户，切换状态重启后仍生效。必须整条消息只有命令且不带引用；`/new 请检查代码`、包含命令的普通句子、带引用的提问都作为普通任务转发。

`/new` 不取消旧任务，也不删除 Raft 历史；旧任务后续回复仍能回到原私聊。它只切换发送目标，不重置 agent 自身记忆或限制其读取频道历史。群聊每条消息本来就独立建任务，发送 `/new` 只提示用法，不会重置其他人的会话。

私聊映射自动保存到 `.local/private-sessions/`，重启后继续使用。文件只保存路由 ID、首条来源消息标识和最近 1,000 条重开命令标识，不复制聊天记录、不保存企微或 Raft 凭据。另保留最近 1,000 个旧私聊线程的回传路由，超出后最旧的路由在重启时不再恢复。Bot、Raft 服务地址、频道或 agent 配置变化会使用不同的映射文件；相同身份仅更换 token 不影响会话。旧版固定线程文件会自动兼容，升级前的独立私聊任务不会合并。

**群聊每次提问独立建任务**。Sol 和其他协作 agent 在对应 thread 中的回复，只送回该群或该私聊。旧私聊线程暂时不可用时会提示，恢复前不会悄悄创建一个新线程。

**Sol 必须在任务对应的 thread 中回复。** 直接发在频道里的消息、未知线程中的消息，即使 `@WeCom` 也无法确定接收方，因此不会转发；不会广播给所有群或发送给最近联系的人。

正常提交时不发送确认或进度提示，回复以 `[Sol] 回复内容` 等形式返回，长文本自动分段。投递失败、空任务或队列已满时仍会提示。过滤桥接自身、人类、系统和其他频道的消息。

可在 Raft 频道告诉 Sol：

> 本频道接入了多个企微群和私聊。请始终在每条任务消息对应的 thread 中回复，完成后一次性给出结论和必要依据。不要发送“收到”“我先检查一下”等开工或进度消息。需要补充信息或遇到阻塞时，在同一 thread 简短说明。用户明确要求进度时再提供。

这条约定由 agent 遵循；桥接不会判断哪条是最终结论，agent 发送的进度消息仍会回传。

## 当前边界

- 仅文本、多企微会话对应一个固定 Raft 频道；没有附件、卡片、后台或数据库。
- 所有任务仍进入同一个 Raft 频道，其成员可以读取这些任务；来源会话路由只负责把回复送到正确的位置。
- 私聊映射保存到本地文件；群聊映射、排队、游标和一般去重记录仍在内存。保留最近 10,000 个回传路由；发送重试复用由 bot、会话类型、会话 ID 和消息 ID 派生的幂等键。
- 回传失败不推进 Raft 游标；已成功发送的分段不重复发送。回执丢失仍可能产生重复，不承诺 exactly-once。
- 重启会恢复已保存的私聊线程，并可回传该线程启动后产生的新回复；群聊旧任务的路由和内存队列不会恢复，停机期间的回复暂不补发。休眠或退出程序后桥接停止。
- 回传依赖桥接身份的 inbox。桥接会关注自己发起的任务线程；关注或解析线程失败时保留待处理路由，重试期间不消费回复，也不重复发起已提交的任务。
- 各种 ID 仅用于程序内部关联及投递日志，不附加到聊天正文。后台模式追加写入 `.local/bridge.stdout.log`、`.local/bridge.stderr.log`，前台模式写终端；停止后可归档或清理日志。

## 开发与验证

```powershell
npm run typecheck
npm test
npm run check
```

测试使用本地 mock 和 WebSocket 服务，不使用真实凭据或触发 Sol。覆盖多会话回信、引用、重试、私聊线程复用、`/new` 持久化及失败回滚，以及实际子进程的后台启动、重复启动、状态查询和正常停止。GitHub Actions 在 Windows、macOS、Linux 上使用 Node.js 22 运行同一套测试。

真实验收：先告知 Sol 上述 thread 规则，再在两个群及私聊分别发不同的测试文本，检查回复只返回各自的会话。单次测试可发送“请在本条任务的 thread 里只回复‘桥接正常’”。
